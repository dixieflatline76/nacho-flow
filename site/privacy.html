Privacy Policy & Security Model

Last Updated: August 21, 2026

Nacho Flow is built from the ground up on the principle of Local-First Sovereignty. It is designed to empower developers with complete control over their agent workflows, prompts, and credentials without third-party surveillance.

1. Zero Third-Party Telemetry

Nacho Flow does not contain analytics SDKs, tracking pixels, or "phone home" telemetry. No usage data, prompt text, or execution logs are ever transmitted to the creators of Nacho Flow or external telemetry collectors.

2. Local API Key Storage

All provider API keys (OpenRouter, DeepSeek, Langdock, Azure OpenAI) remain strictly on your local machine. They are loaded at runtime from environment variables or your local config.yaml file and are only transmitted directly over TLS to the specific upstream providers you configure.

3. Direct Upstream Communication

When a request is evaluated by Nacho Flow:

  • Local Turns: Sent directly to your local daemon (e.g. Ollama or vLLM on 127.0.0.1). Traffic never leaves your local network.
  • Cloud Turns: Dispatched via standard encrypted HTTPS directly to the configured endpoint (e.g. https://openrouter.ai/api). No intermediary proxies or cloud relay servers are used.

4. Local Diagnostics & Logs

Session stats, token counts, and routing traffic logs (traffic.jsonl, stats.json) are stored strictly on your local disk in your user config directory. You can inspect, wipe, or disable traffic logging at any time.

5. Open Source Auditing

The entire source code of Nacho Flow is open source under the MIT License and subject to continuous automated static security analysis (gosec). You can inspect and verify every network request in the codebase on GitHub.

6. Questions or Privacy Concerns?

If you have questions about this privacy policy or want to report a security concern, please reach out at info@spicebox.dev or visit the Support page.
